## 🧭 رؤية الكورس ومنهجية العمل (The Philosophy)
الانتقال من التلقي النظري إلى **عقلية المهندس المبتكر (Zero-Fluff / Production-First)**:
* **التطبيق الحي الفوري:** كل مفهوم نظري يتم تحويله بلحظتها إلى كود يعمل داخل المتصفح.
* **البناء التراكمي:** تطوير نظام إدارة مبيعات وأقساط المتاجر خطوة بخطوة من واجهة محلية إلى نظام سحابي ذكي.
* **البيئة الاحترافية:** اعتماد محرر VS Code، تتبع النسخ بنظام Git، والنشر المباشر عبر خوادم GitHub Pages.

### 🔹 اليوم الثاني: هندسة التخزين، Git، والنشر الحي (Production & Deployment)
* **تاريخ الإنجاز:** 2026-11-08
* **الهدف:** الانتقال إلى الإصدار 2.0، حل فقدان البيانات بالرفرش، ضبط نظام Git، ونشر المشروع برابط عام.

#### 1. ما تم تعلمه وتطبيقه هندسياً:
* **معمارية التخزين (`localStorage` vs RAM):**
  * **الـ RAM:** تحتفظ بالبيانات أثناء الجلسة فقط وتفرغ الحقول عند إعادة التحميل.
  * **الـ `localStorage`:** خزانة متصفح محلية تحفظ السجلات بشكل دائم.
  * **تسلسل البيانات:** استخدام `JSON.stringify()` لتحويل الكائنات إلى نصوص للحفظ، و `JSON.parse()` لإعادة بنائها عند الفتح.
* **التحكم بالإصدارات (Git):**
  * إعداد الهوية البرمجية من الـ Terminal:
    ```bash
    git config --global user.name "Abood"
    git config --global user.email "engabdullah3d@gmail.com"
    ```
  * معالجة مشكلة مسارات النظام (PATH) بإعادة تشغيل البيئة.
  * إدارة دورة حياة الكود: من التعديل (`Working Directory`) إلى الإيداع (`Commit`) ثم الرفع السحابي (`Push`).
* **الاستضافة السحابية (GitHub Pages):**
  * رفع المستودع إلى GitHub وتفعيل الاستضافة على فرع الإنتاج (`main`).

#### 2. المخرجات والنتائج الحية:
* **إطلاق الإصدار 2.0:** توليد وصولات حساب مخصصة، نسخ رسائل واتساب بضغطة واحدة، وأرشفة السجلات بالمتصفح.

* **الاستيعاب المعماري:** فهم الفارق بين الـ Frontend المعزول وحاجة الأنظمة المتزامنة لخادم مركزي وقاعدة بيانات سحابية.
